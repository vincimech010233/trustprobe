# Arquitectura y datos

**VERIFIED:** `data/build_dataset.py` genera `data/exercises.json`; `trustprobe/core.py` selecciona y puntúa; `trustprobe/store.py` conserva estado en SQLite; `trustprobe/web.py` sirve API y archivos estáticos sólo en `127.0.0.1`; `static/` muestra el flujo; `scripts/simulate.py` recorre la misma API de almacenamiento que la interfaz.

Tablas: `sessions` (id aleatorio, semilla, orden/variantes, fase, posición, versión de esquema y marcas de tiempo), `attempts` (B, confianza pre-IA, condición, J, confianza en J, F, confianza post-IA, razón opcional, diagnóstico/corrección, ítem paralelo y tiempos separados), `events` (inicio y un envío por cada fase con marca temporal). `condition` admite `ai_correct`, `ai_incorrect` y `no_ai_control`; el flujo actual solo ejecuta las dos condiciones IA. Los nombres internos `transfer_*` describen el ítem paralelo y se conservan por compatibilidad. La columna histórica `confidence` se migra a `ai_judgment_confidence`; no se reutiliza como confianza propia. Las sesiones antiguas completadas conservan F ausente; las antiguas incompletas piden iniciar una sesión nueva sin inventar datos. Son datos estructurados del **prototipo**, no la bitácora operacional del repositorio raíz. Se evita almacenar nombre, correo, IP o identificadores escolares; un campo libre podría contener datos que introduzca quien lo use, por eso el README pide no introducirlos.

El servidor valida fases para impedir doble envío y calcula tiempos en el servidor. La selección usa `random.Random(seed)` local; una misma semilla reproduce orden y variantes con la misma versión de Python/banco. El navegador guarda sólo el id de sesión. No hay red de salida ni GPU. Las respuestas esperadas residen en el servidor y no en JSON público durante la sesión. La base de datos local no está cifrada: para un estudio real requiere control de acceso, retención y política de datos.
